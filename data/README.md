# `data/` — inputs expected by the R analyses

Only the small tables that are needed to follow the analyses and that do not
belong to a third party are stored here. Everything is read through the
`CS_DATA` variable defined at the top of each R script (default: this folder),
so the layout below is all a reader has to reproduce.

```
data/
├── metadata.txt         # 15 samples: treatment, category, day, replicate flag, colours
├── metadata2.txt        # same design plus the total ARG abundance per sample
├── 16S/
│   ├── oturaw.txt       # ASV counts (15 samples x 1 131 ASVs), usearch -otutab
│   ├── sintax.txt       # SINTAX / MiDAS 4.8.1 taxonomy of the ASVs (1 201 hits)
│   ├── asv_lefse_*.txt  # LEfSe input tables written by the LEfSe section
│   ├── kw.list.txt      # Kruskal-Wallis output for the random-forest taxa
│   └── spec_occu_specialist_all.txt   # SPEC-OCCU specialists, kept as reference
├── MAGs/
│   ├── bins_abundance_tpm.tsv         # MAG abundance (TPM) per sample
│   ├── gtdbtk.bac120.summary.tsv      # GTDB-Tk taxonomy of the 257 MAGs
│   └── plasmid_result.txt             # PlasFlow plasmid counts per MAG
├── ARG/                 # ARGs-OAP output (normalized_cell.*.txt, rpkm/ppm.type.txt)
├── MRG/                 # MRGs-OAP output (normalized_cell.level2/level3.txt)
├── aromadeg/            # ADG output (normalized_cell.level1/level3/level4.txt)
├── MGE/                 # MGE output (normalized_cell.level2/level3.txt)
├── ARG/jili2/           # mechanism-grouped ARG table
├── reviewers/           # tables added for the reviewer round (metadata22.txt, ...)
└── db/SARG/             # SARG structure file and ARG rank list
```

The folders `ARG/`, `MRG/`, `aromadeg/`, `MGE/`, `ARG/jili2/`, `reviewers/` and
`db/` are **not populated** in the repository: they hold the output of
`pipelines/04_gene_abundance/06_args_oap_gene_abundance.sh` (ARGs-OAP) and of
`pipelines/03_resistance_gene_annotation/` (diamond), which are too large to
distribute and are regenerated by the pipelines. `docs/04_script_inputs_outputs.md`
lists the exact file names every section expects.
